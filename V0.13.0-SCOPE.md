# Hidden Conviction v0.13.0 Scope

Theme: architecture simplification and performance.

## 1. Route-specific HTML

- [x] Home, Company, System, and Methodology are separate physical HTML documents.
- [x] The public response never ships hidden markup for unrelated routes.
- [x] Route metadata is unique for title, description, canonical URL, and OpenGraph.

## 2. Unambiguous SSR

- [x] Home SSR is rendered at the public edge from D1.
- [x] Company and System SSR are rendered into route-specific HTML before response.
- [x] Raw-origin browser tests assert initial HTML rather than relying on hydration.
- [x] HEAD and conditional ETag behavior remain supported.

## 3. Performance

- [x] Public page serving moved off Python/FastAPI to a lightweight JavaScript Worker.
- [x] Home reads D1 directly and records query timing.
- [x] Bundle and TTFB budgets are enforced in deployment.
- [x] Public edge reports deployment/build identity in response headers.

## 4. Worker architecture split

- [x] `hidden-conviction` is the public JS edge Worker.
- [x] `hidden-conviction-ingest` owns Python ingestion, scoring, queues, cron, and API logic.
- [x] `hidden-conviction-13f` remains isolated for 13F processing.
- [x] Public to backend calls use a Cloudflare service binding.
- [x] Deployment orders backend first and public cutover last.
- [x] Ingestion secrets are verified before public cutover.

## 5. Python entrypoint refactor

- [x] Browser rendering removed from `main.py`.
- [x] Operational telemetry helpers moved to `src/telemetry.py`.
- [x] Public edge rendering moved to `src/public_worker.js`.
- [x] Existing ingestion/scoring behavior remains regression-tested.

## 6. Cache and build identity

- [x] Critical build/health endpoints stay `no-store`.
- [x] Every public response carries version, API schema, build ID, and deployment ID headers.
- [x] Build fingerprint is generated for both Python and JavaScript runtimes.
- [x] Production verification compares endpoint versions and raw page headers.

## 7. Database performance and observability

- [x] Add targeted score, ticker, processing, and recompute indexes.
- [x] Add `query_metrics` with executions, rows, total/max duration, and slow counts.
- [x] Public home read path records query timings.
- [x] Admin exposes fixed `EXPLAIN QUERY PLAN` output for high-value read paths.
- [x] Regression test verifies the company-score query uses the new index.
- [x] Migration rollback behavior is tested transactionally.

## 8. System Console 2.0

- [x] Pipeline flow visualization.
- [x] Expandable stage diagnostics.
- [x] Recent cron history.
- [x] Recent pipeline errors.
- [x] Seven-day pipeline activity and latency rows.
- [x] Query performance telemetry.
- [x] Existing authenticated one-click filing/score replay retained.

## 9. Testing and quality gates

- [x] Raw-origin Playwright route-specific SSR checks.
- [x] Accessibility checks with Axe.
- [x] Visual regression screenshot artifacts.
- [x] Production performance budgets.
- [x] Migration rollback regression test.
- [x] Coverage reporting with an initial 30% floor; current measured baseline is 34%.
- [x] Python, JS, shell, migration, and configuration validation.

## 10. Codebase hygiene

- [x] Runtime/dev tool versions pinned.
- [x] Git build SHA/build ID remains canonical deployment identity.
- [x] Release-note generation script added.
- [x] Generated local admin secret and coverage artifacts excluded from Git.
- [x] Deployment scripts are version-aware and backend-first.
